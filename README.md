## Портфолио

Закрытые материалы прошлых работодателей не публикуются. Открытые реализации ниже созданы отдельно на синтетических данных. Они не подтверждают масштабы или экономию в компаниях.

### Ассистент для адаптации новичков

- Задача: Сотруднику нужно быстро найти порядок действий, а наставник регулярно отвечает на одинаковые вопросы.
- Опыт / статус: Создавал RAG-ассистента для новичков, который помогал в обучении и поиске информации.
- Открытая реализация: Открытый прототип поиска по синтетической базе инструкций: вопрос, подходящий фрагмент, источник. Если ответа нет, система сообщает об этом. Генеративная модель в публичной версии не подключена.
- Метрики для внедрения: Время поиска правильной инструкции, доля ответов с подходящим источником, число обращений к наставнику.

### Внутренняя CRM для сотрудников

- Задача: Обращения и следующие действия теряются между перепиской и таблицами.
- Опыт / статус: Создавал собственную CRM-систему для сотрудников. Участвовал в настройке Битрикс24 и amoCRM с помощью AI или коллег.
- Открытая реализация: Демонстрация карточки обращения: создание, ответственный и этап. Записи сохраняются в браузере, можно изменить статус и удалить тестовые данные.
- Метрики для внедрения: Полнота карточек, число потерянных обращений, время регистрации заявки.

### Контроль качества звонков

- Задача: Руководителю нужен понятный список моментов, которые стоит разобрать с сотрудником.
- Опыт / статус: Самостоятельный демонстрационный проект для портфолио.
- Открытая реализация: Проверка учебной расшифровки: приветствие, уточнение задачи и следующий шаг. Показаны найденные фразы. Оценку проверяет человек; это правила, а не распознавание аудио или LLM-анализ.
- Метрики для внедрения: Совпадение с ручной оценкой, пропущенные нарушения, время разбора звонка.

### Обработка заявок и контроль интеграций

- Задача: Повторная доставка события может создать дубль, а неполная заявка мешает дальнейшей работе.
- Опыт / статус: Самостоятельный демонстрационный проект для портфолио.
- Открытая реализация: Локальная модель обработки событий: проверка полей, защита от повторной обработки по ID в пределах одного запуска, отметка неполных заявок и журнал результата. Никакие сообщения клиентам не отправляются.
- Метрики для внедрения: Дубли после повторной доставки, доля неполных заявок, успешные и отклонённые события.

[Открыть интерактивные демонстрации](https://m1trotrabota-source.github.io/m1trotrabota-source/#work) · [Код сценариев](demos.js)
